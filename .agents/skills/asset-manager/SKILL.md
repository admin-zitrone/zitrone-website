# Asset Manager

Zitrone has ONE asset system shared by the website and the deck system. Everything
served lives under `public/img/*`; it is **generated** from a registry. Your job is to
go through the registry, never around it. Full reference: `ASSETS.md` at repo root.

## The contract — ONE library, ONE registry, no duplication

`public/img/` IS the single canonical library (there is NO separate master tree — an image
exists once). It is organized by OWNERSHIP so the website and deck system aren't mixed:
- `public/img/shared/` — used by BOTH (services photography, clients logos, brand, media, food,
  hero, service-detail, featured-spread). The efficient core every deck + the site references.
- `public/img/site/` — website-ONLY chrome (operations, testimonials, service-cards, hero-dining-hall).
- `public/img/deck/` — reserved for deck-ONLY assets.

**Edit only these:**
- `public/img/{shared|site}/…` — drop & name image files here directly (kebab-case).
- `assets.manifest.json` — the registry: `files[]`, `clients[]`, `media[]`, `brand[]`, `tags`.

**Never hand-edit (generated by `scripts/assets-sync.mjs`):**
- `src/lib/assets.generated.ts` — the website's typed map.
- `deck-system/data/brands.json` — the deck logo wall (from `clients[]`).

After any change run **`npm run assets:sync`** (also runs on predev/prebuild).
`npm run assets:check` is the drift gate — it fails the build if a referenced file is missing
or a generated file is stale. Decks + website both reference `public/img` paths; never copy an
image per-client or per-deck — reference the one shared file.

## NOMENCLATURE — non-negotiable

Every file AND folder is lowercase **kebab-case**, descriptive, scalable, repeatable:

- ✅ `make-your-own-bowl-station.jpg`, `coca-cola-wide.svg`, `chef-plated-dish.jpg`,
  `services/comedor/`, `clients/mono/`
- ❌ NEVER: spaces, `_`, CAPS/Title_Case, `()`/`&`, bare numbers (`01.jpg`), tool dumps
  (`ChatGPT Image Jun 10…png`), camera exports (`Z_MARZO_26-320.jpg`), vague (`img1`).

Name by **what it depicts** (`buffet-toppings-bar`), not by sequence or source. Pattern:
`<subject>-<qualifier>.<ext>`. If you can't name it meaningfully, look at the image first.

**Logo variants are organized by FOLDER, never by suffix** — the folder is the variant,
the filename is always just `<brand>.svg`:
- `img/clients/<brand>.svg` — primary full-color mark (default; the logo wall uses these)
- `img/clients/wide/<brand>.svg` — horizontal / lockup version
- `img/clients/mono/<brand>.svg` — monochrome (hero ribbon, dark backgrounds, testimonial cards)

Never `coca-cola-wide.svg`, `pg-mono.svg`, `*-blackandwhite.svg`, `*-stacked-horizontal.svg`.
In the manifest a client carries `logo` / `logoWide` / `logoMono` accordingly. (A brand that
needs two monos — e.g. a mark-mono and a wide-mono — may use `mono/<brand>-wide.svg`; that
shape qualifier inside `mono/` is the only allowed suffix.)

## How to… (pick the matching recipe)

**Use an image on the website** — import by id, never a literal path:
```ts
import { assetSrc, asset } from "@/lib/assets.generated"
<img src={assetSrc("food-pizza-station")} alt={asset("food-pizza-station").alt} />
```
Find ids/tags in `assets.manifest.json` or via `assetsByTag("service:comedor")`.

**Add / replace a website image**
1. Drop the file directly in `public/img/site/<bucket>/` (website-only) or
   `public/img/shared/<bucket>/` (if decks may use it too), kebab-named.
2. Add/repoint its `files[]` entry in `assets.manifest.json` (`id`, `public` `/img/…`, `alt`, `tags`).
3. `npm run assets:sync`, then reference it by `assetSrc("<id>")`.

**Add deck / service-section photography**
1. Drop the photo straight into `public/img/shared/services/<section>/` (kebab name).
2. `assets-sync` folds it into the index automatically (id `<section>-<name>`). Reference in slides
   as `/img/shared/services/<section>/<name>.jpg` (or by id on the site). No manifest entry needed.

**Add a client (cascades to the deck logo wall)**
1. Drop the logo in `public/img/shared/clients/<id>.svg` (+ `wide/<id>.svg` / `mono/<id>.svg`).
2. Add a `clients[]` entry: `id`, `name`, `logo`, optional `logoWide`/`logoMono`/`photo`/`scale`, `wallRow`, `lead`.
3. `npm run assets:sync` → `brands.json` regenerates; the Aliado wall updates next deck build.

**Rename / clean up an asset**
1. Rename the file in `public/img/...` to a compliant kebab name.
2. Update its `assets.manifest.json` entry (and `id` if the old id encoded the bad name).
3. Rewrite every reference (site `assetSrc` ids + literal paths in `deck-system/**`,
   `preview/**`, `public/decks/**`). Grep the OLD path repo-wide to be exhaustive.
4. `npm run assets:sync`.

**Find the canonical image for a topic** (or building a new one-pager / deck):
filter `tags` in `assets.manifest.json` (e.g. `assetsByTag("equipment:coffee-machines")`), or
browse `public/img/shared/`. One shared file per asset — reference it, never copy it per deck.

## Always finish with

`npm run assets:check` → `npx tsc --noEmit` (no NEW errors) → `node deck-system/check.mjs`
(0 errors) → confirm the page/slide renders. Grep the repo for any leftover legacy/old
path. Never leave a non-kebab file under `public/img` (the only allowed exception is the
`_STANDIN-README.txt` placeholder markers in deck section folders).
